# VERA Snapshot Schema

Data contract for the dashboard payload generated by `build_snapshot.py` and consumed by the frontend via `dashboard.json`.

**Version**: 2026-03-26c
**Owner**: VERA pipeline

---

## Top-level keys

| Key | Type | Volatile | Description |
|-----|------|----------|-------------|
| `generated_at` | ISO 8601 | yes | When the snapshot was built |
| `app` | object | no | Static app metadata |
| `snapshot` | object | no | Build status and paths |
| `vera` | object | partial | VERA runtime status |
| `publish` | object | yes | Deploy/publish state |
| `stages` | object | yes | Per-stage pipeline state |
| `run` | object | yes | Latest run metadata |
| `source_health` | object | yes | Aggregate + per-source health |
| `summary` | object | no | Recommendation counts and hero text |
| `pipeline` | object | no | Discovery mode and stage counts |
| `messages` | array | no | VERA log messages for the dashboard |
| `shortlist` | array | no | Top-scored listings |
| `reviewed_out` | array | no | Filtered/manual-review listings |
| `risk_watch` | array | no | Red-flag listings |
| `sources` | array | no | Enabled source configs merged with raw manifest |
| `stats` | array | no | Pipeline stat chips |
| `artifacts` | array | no | Downloadable file links |
| `state_buckets` | object | no | Full bucketed listing inventory |
| `recommendations` | array | yes | Run-level action recommendations |
| `run_trends` | array | yes | Last 7 run summaries for trend analysis |
| `listing_confidence` | object | yes | Aggregate confidence distribution across scored listings |

**Volatile** keys are excluded from the content hash used for deploy gating.

## `stages` (object, keyed by stage name)

Stage names are ordered: `discover`, `normalize`, `dedupe`, `enrich`, `score`, `publish`.

```jsonc
{
  "discover": {
    "status": "success",       // enum: success | running | error | blocked | partial | unknown
    "started_at": "ISO 8601",
    "finished_at": "ISO 8601",
    "run_id": "hourly_20260327-050447",
    "records_in": 0,           // input count (0 for discover)
    "records_out": 184,        // output count
    "errors": [],              // array of error strings
    "blocked_reason": null,    // string if status=blocked (publish only)
    "publish_outcome": null    // string if stage=publish (e.g. "deployed_and_verified")
  }
}
```

### Status enum (tight — do not extend without updating frontend)

| Status | Meaning | Frontend color |
|--------|---------|---------------|
| `success` | Completed normally | green |
| `partial` | Completed with some issues, data usable | amber |
| `running` | Currently executing | amber (animated) |
| `error` | Failed | red (solid border) |
| `blocked` | Prevented from starting (prerequisite failed) | red (dashed border) |
| `unknown` | No state file found | grey |

## `source_health` (object)

```jsonc
{
  "active": 8,
  "healthy": 5,
  "partial": 2,
  "broken": 1,
  "sources": [
    {
      "name": "craigslist",
      "source_class": "market",    // market | affordable | editorial | verification | fallback
      "cadence": "hourly",
      "status": "healthy",         // healthy | partial | broken
      "records_found": 42,
      "parser_version": "2026-03-27a",
      "confidence": 0.91,
      "reliability_score": 87,     // 0-100 composite
      "last_attempted_at": "ISO 8601",
      "last_successful_at": "ISO 8601",
      "anomaly_flag": false,
      "anomaly_reason": null,
      "extraction_strategy": "json_ld"
    }
  ]
}
```

### Source class enum

| Class | Sources | Description |
|-------|---------|-------------|
| `market` | craigslist, streeteasy, renthop | Standard market rental listings |
| `affordable` | housing_connect, hdc_hpd_rerentals | Public/affordable housing programs |
| `editorial` | listings_project, nooklyn | Curated/editorial listing sources |
| `verification` | (NYC Open Data APIs) | Building verification data, not listings |
| `fallback` | leasebreak, nybits, spareroom | Bridge/temporary or secondary sources |

### Reliability score components (0-100 composite)

| Component | Weight | Description |
|-----------|--------|-------------|
| Parser confidence | 30% | Extraction strategy confidence from discover |
| Success rate | 25% | Successful runs / total runs over 7-day window |
| Freshness | 20% | How recently the source last returned data |
| Anomaly status | 15% | Penalize if anomaly flagged |
| Record stability | 10% | Records vs 7-day trailing average |

## `sources[]` (array)

Merged from `source_catalog.json` config and raw manifest data. Contains all catalog fields plus runtime fields from the latest discover run (`record_count`, `status`, `fetched_at`, etc.).

## `source_health.sources[].recommended_actions` (array of strings)

Max 3 per source. Only present for degraded sources.

Example: `["Parser confidence low (42%). Review selector strategy for html_table extraction."]`

## Source-specific alert thresholds

Defined in `source_catalog.json` per source:

```jsonc
{
  "alert_thresholds": {
    "confidence_min": 0.5,      // default 0.6
    "drop_threshold_pct": 65    // default 50
  }
}
```

Noisier sources (craigslist) get wider thresholds. Structured sources (housing_connect) can have narrower thresholds.

## Per-listing confidence fields (on each listing in shortlist/reviewed_out/risk_watch)

Each listing record includes these fields computed by `listing_confidence.py`:

| Field | Type | Description |
|-------|------|-------------|
| `listing_confidence_score` | int (0-100) | Composite trust score |
| `listing_confidence_band` | string | `high` (≥75), `medium` (50-74), `low` (25-49), `needs_review` (<25) |
| `listing_confidence_breakdown` | object | Per-component `{raw, weight, points}` |
| `why_this_listing` | string | Human-readable trust narrative |
| `trust_strengths` | array of strings | Plain-English trust signals (max 4) |
| `trust_caveats` | array of strings | Plain-English concerns (max 3) |

### Confidence components (weights sum to 100)

| Component | Weight | Description |
|-----------|--------|-------------|
| `source_reliability` | 25 | Reliability of source(s) this listing came from |
| `source_redundancy` | 15 | How many independent sources confirm it |
| `address_quality` | 15 | Address normalization and geocoding confidence |
| `verification_match` | 20 | Building verification against public records |
| `freshness` | 10 | How recently the listing was seen |
| `field_completeness` | 10 | How many important fields are populated |
| `consistency_checks` | 5 | Internal consistency of listing data |

### Confidence breakdown example

```jsonc
{
  "source_reliability": {"raw": 0.87, "weight": 25, "points": 22},
  "source_redundancy": {"raw": 0.80, "weight": 15, "points": 12},
  "address_quality": {"raw": 0.75, "weight": 15, "points": 11},
  "verification_match": {"raw": 1.00, "weight": 20, "points": 20},
  "freshness": {"raw": 0.85, "weight": 10, "points": 9},
  "field_completeness": {"raw": 0.70, "weight": 10, "points": 7},
  "consistency_checks": {"raw": 1.00, "weight": 5, "points": 5}
}
```

These fields appear in `sections.confidence` and `sections.narrative` within each listing record.

## Versioning

Changes to this schema should:
1. Update the version at the top of this file
2. Be backwards-compatible (add fields, don't remove or rename)
3. Update the frontend to handle missing fields gracefully (always use `?.` and fallbacks)
