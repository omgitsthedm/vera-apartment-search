# NYC Apartment-Hunt Derivations

Three small, ready-to-use derivations of NYC public data, produced for
[VERA](https://littlefightnyc.com/vera) — an apartment-search engine that
verifies listings against city records. Published because the derivation
step is the annoying part, and nobody should have to redo it.

Every file is generated by a script in
[omgitsthedm/vera-apartment-search](https://github.com/omgitsthedm/vera-apartment-search);
nothing here is hand-edited.

## Files

### `transit_stations.json` — 496 subway stations

Parent stations from MTA GTFS static, each with its **true served line set**
— derived from the actual trip and stop-time graph rather than a
hand-written table — plus coordinates.

```json
{"id": "636", "name": "Astor Pl", "lat": 40.73005, "lon": -73.99107,
 "lines": ["4", "6", "6X"]}
```

Built by `scripts/refresh_transit_gtfs.py`. Refresh weekly; the script
caches the ~5MB GTFS zip for seven days.

### `transit_routes.json` — scheduled ride times

Per route, one representative stop sequence with **cumulative seconds from
the first stop**, so the ride between any two stations on a line is a
subtraction rather than a guess. 29 routes.

```json
{"L": [["Canarsie-Rockaway Pkwy", 0], ["East 105 St", 90], ...]}
```

### `nta_hoods_full.json` — 197 neighborhood polygons

Every residential NTA2020 neighborhood across all five boroughs, from the
NYC Department of City Planning (open-data id `9nt8-h7nd`), simplified with
Ramer–Douglas–Peucker to roughly 22m. 168KB — small enough to ship to a
browser and run point-in-polygon locally.

```json
{"bounds": {...}, "hoods": [{"n": "Greenpoint", "b": "B", "a": "Grnpt",
 "r": [[[40.7282, -73.9321], ...]]}]}
```

Rings are `[lat, lon]` — note the order, GeoJSON is the reverse. Built by
`scripts/build_nta_polygons.py`. Refresh only when DCP publishes a new NTA
vintage, which is rare.

## Why these exist

Walk and ride estimates in housing tools are usually invented. These let you
quote the timetable instead: VERA prints "≈4 min walk to 1 Av, then the L"
and every one of those numbers traces to a public file.

The walk estimate is still approximate — straight-line distance × 1.3 for
street detour at 80 m/min — and is always marked ≈ in the product. The
**ride** time is scheduled, not estimated. That distinction is the whole
point of publishing these.
